# Plan: Call it 1.0

## The approved decisions, carried over

**One line.** `manifest.json:5` is the only version in the tree; `flake.nix`
reads it with `builtins.fromJSON` and names the store path from it.

**Merge, verify, then tag.** The bump lands through a normal PR, CI passes on
`master`, `nix build` confirms the store path says `1.0.0`, and only then is
the tag cut — annotated, on that exact commit. A tag is what people pull.

**Marked latest, not pre-release.** The caveat goes in the notes, not in
metadata.

**Notes are written, not generated**, in three sections: what changed, what
was verified live, and **what was not** — the last being its own section
because #19's stop-all confirmation has never been seen by a human.

**#38's videos and the host wiring do not block**, and the notes say why.

## Steps

1. **`manifest.json`: `0.2.0` → `1.0.0`.**
   → verify by `jq -r .version manifest.json` and by `nix build` producing a
   path ending `-nixarchy-podman-1.0.0`.

2. **PR and merge**, with CI green on the PR and again on `master`.
   → verify by `gh pr checks` and `gh run list --branch master`.

3. **Tag**: `git tag -a v1.0.0` on the merged commit, message naming what the
   release is, then push the tag.
   → verify by `git rev-parse v1.0.0^{}` equalling `git rev-parse master`.

4. **Release**: `gh release create v1.0.0` with the written notes, marked
   latest, no binary artifact — the plugin installs by clone or flake.
   → verify by `gh release view v1.0.0`.

5. **Install check on the tag**, because that is how people will get it:
   clone the tag into a temp dir, strip `.git`, and run
   `omarchy plugin validate`.
   → verify by validate passing.

## Tests

```bash
jq -r .version manifest.json          # 1.0.0
nix build && readlink -f result       # …-nixarchy-podman-1.0.0
node tests/run.js                     # 175
nix flake check                       # all checks passed
git rev-parse v1.0.0^{} == master     # same commit
```

No live desktop verification: a version bump changes no behaviour. The
release notes record what live verification has and has not been done across
the work being released.

## Rollback

Before the tag: revert the bump commit, nothing else exists.

After the tag: `gh release delete v1.0.0` and `git push origin :v1.0.0`
remove it, but anyone who pulled in between has it — which is why the tag
comes last and only after green CI. A bad release is corrected by `1.0.1`,
not by deleting history.
