# Intent: Minor UI polish from the #10 live test

## Problem

The live test pass for #10 (razer, 1920×1080, Podman 5.8.6, omarchy 4.0.4) found
five small defects. At #10's intent approval they were set aside as a separate issue.
None of them loses data, but each makes the panel harder to read or to aim at.

1. **The shortcut sheet is see-through.** With `?` open, the list rows show between
   the sheet's lines, for example "demo-shop-db" behind the CONTAINERS heading and
   the footer behind "?". `ShortcutSheet.qml` draws its background at 0.97 opacity,
   which should hide the rows almost completely, so the cause is still unknown. It
   may be drawing order, or the menu's 1.45× scale.
2. **The sheet leaves out `Tab`.** In the full-screen menu, `Tab` moves to the next
   tab, and the user guide says so. The sheet (`Model.SHORTCUTS`) does not list it.
3. **The menu card jumps when you change tab.** `Menu.qml` places the card at a third
   of the leftover height, so every tab with a different number of rows moves the
   tabs and the filter up or down under the eye.
4. **Rows move under the pointer after a click.** Starting or stopping a container
   re-sorts the list (running first). A second click at the same spot then lands on
   a different container. In the test, clicking ▶ on demo-shop-web moved it to the
   top, and the rows below shifted.
5. **Podman's refusal line is cut short and needs the mouse.** `Model.errorText` keeps
   160 characters, and the line showed as two lines ending in "force-…". The only way
   to dismiss it is its × button; no key does it.

## Proposed outcome

- With the shortcut sheet open, nothing from the list shows through it, in the popup
  or the menu.
- The sheet lists every key the surface responds to, including `Tab` in the menu.
- Switching tabs in the menu does not move the tab strip or the filter.
- A row does not move away between the click that changes it and a second click
  straight after, or the risk is otherwise removed.
- Podman's refusal reads in full, or at least up to its actionable part, and can be
  dismissed from the keyboard.

## Affected users and systems

- `ShortcutSheet.qml`, `Menu.qml`, `PodmanView.qml`, `ResourceList.qml`, and
  `Model.js` (`SHORTCUTS`, `errorText`) with its tests.
- `docs/usage.md` and the README key table, if a key is added.
- Captures: `shortcuts.png` and `podman-refuses.png` would change. The retake is
  tracked in #11.
- Every user of either surface.

## Constraints

- `AGENTS.md`: logic in `Model.js` with Node tests; no hardcoded colours; a
  user-visible change updates the docs in the same PR.
- No new key may collide with an existing one (`Model.SHORTCUTS`), in either surface.
- Live verification on a nixarchy desktop, with `demo-*` objects only and the safety
  rules from #10's plan: screenshot every dialog before confirming anything.

## Open questions

1. **Item 4: what should happen?** Pick one:
   - (a) hold the order briefly after a click, so the row stays put until the pointer
     leaves the list;
   - (b) stop re-sorting by running state altogether, and sort by name within each
     project;
   - (c) leave the order alone, and ignore a second click on a row for a moment after
     it moved.

   I recommend (a). The running-first order is useful, and the problem is only the
   moment right after a click.
2. **Item 5: which key dismisses the error line?** Suggested: `esc`, but only while
   the line is showing. Today the first `esc` on the list closes the panel, so this
   changes what `esc` does in that one state. The alternative is a new key such as
   `e`.
3. **Should all five land in one PR?** I recommend yes, with one plan step each; every
   item is small.
