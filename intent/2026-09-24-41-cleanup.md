# Intent: The review's last findings, still in the code

## Problem

The 2026-09-24 review produced a ranked list. Seven issues came out of it and
all seven are closed. These four items never became issues and are still
here, verified against `master` at `2b04fd8` immediately before filing.

**Two symbols are genuinely dead.** `Model.js:1212`'s `containerById` is a
one-line alias for `itemById`, and grepping the whole tree for it returns
exactly one line — its own definition. `ResourceList.qml:44`'s
`signal activated(string id)` is declared and never emitted. Dead code in a
file AGENTS.md says carries all the logic is a small tax on every future
reader, and this repository's own standard is to delete rather than keep.

**One symbol I twice called dead is not.** `Model.js:985`'s `rowsFor` has
fourteen direct call sites in `tests/model/resources.test.js`, plus
`harness.js:71` and a test named after it. What is true is narrower: it has no
QML caller. Production calls `rowsForSections(sections, tab)`; `rowsFor`
hardcodes `"containers"`. So it is a test-only convenience wrapper. I should
have checked that before repeating the claim.

**Three helpers are live and untested.** `copyTooltip`, `itemKey` and
`labelMap` are each called from `Model.js` or QML and named by no test.
`itemKey` is the one that matters: it exists for the image-tag-collision fix
(#6), the rowId-versus-id distinction that stopped stale duplicate rows, and
nothing asserts it directly. `labelMap`'s object-form branch handles Podman
5's JSON labels and is reached today only through string-form fixtures —
the Qt-sequence-wrapper shape AGENTS.md warns about. `copyTooltip` has four
wording branches, none asserted.

## Proposed outcome

- Nothing in `Model.js` or the drawing components is unreachable.
- A reader can tell from the source which functions production uses and which
  exist for tests, without grepping.
- The three helpers have tests that fail if their behaviour changes —
  particularly `itemKey`, which guards a fix that a real user hit.
- `node tests/run.js` stays green throughout, and no behaviour changes.

## Affected users and systems

- `Model.js`, `ResourceList.qml`, `tests/model/`.
- Future readers and agents working in this repository, which is most of the
  value here — none of this is visible to a user of the plugin.
- No runtime change, no packaging change, no capture affected.

## Constraints

- **No behaviour change.** The deletions remove unreachable code; the tests
  pin behaviour that already exists. If a new test fails when written, that is
  a finding to report, not something to adjust the test around.
- Logic stays in `Model.js` with a Node test (AGENTS.md).
- `Panel.qml` stays byte-identical, as through every change today.
- `nix flake check` must pass, including the checks added by #24 and #30.

## Open questions

1. **Delete `rowsFor`, or comment it?** Removing it means rewriting fifteen
   call sites to gain nothing at runtime, and the tests that use it are
   container-row tests, so its hardcoded tab is correct for them. A comment
   saying "test-only; production calls rowsForSections" costs one line. The
   approver should pick, knowing I previously mis-stated this as dead code.
2. **Should `labelMap` get an object-form fixture**, or is the string-form
   coverage enough? Adding one means asserting behaviour against a Podman
   version whose output I have not seen on this machine — the risk is writing
   a test that encodes my assumption rather than Podman's reality.
3. **Is `copyTooltip` worth four assertions**, or is one enough to catch a
   wholesale breakage? It is wording, not logic, and over-testing wording
   makes it tedious to improve.
