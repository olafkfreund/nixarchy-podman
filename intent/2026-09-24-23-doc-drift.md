# Intent: The documentation contradicts itself and the code

## Problem

This repository has three documentation surfaces — `README.md`,
`docs/usage.md` and the site's `docs/index.md` — and AGENTS.md requires a
user-visible change to update them in the same PR. That has mostly happened.
Where it has not, the surfaces now disagree with each other and with the
plugin, and a reader has no way to tell which one is lying.

**Flat contradictions between two documents.**

`README.md:136` says the menu reads settings "each time it opens".
`docs/usage.md:195` says it picks them up "only after the shell restarts,
because of an Omarchy shell issue". Commit `4d5c30f` (#10) changed usage.md
and left the README behind. `Menu.qml:70` does call `readSettings()` on every
`open()` — but it reads through `shell.barConfig`, which may itself be stale,
so the code does not settle it either. Someone has to look at a running
shell.

`README.md:35` says the footer reports what the current tab holds.
`docs/usage.md:111` says images and volumes only. `Model.usageText`
(`Model.js:661-677`) covers Containers too, so usage.md is the wrong one.

`README.md:60` duplicates `README.md:55` — two `tab` rows in one table with
the clauses reversed. `Model.js:83-84` asserts that "the README quotes it, so
the two can never drift apart"; the README table has eight rows where `?`
renders seven, so they have drifted apart and the comment is now false.

**Things the plugin does that nothing documents.**

Shift+Tab and Backtab step backwards through the tabs
(`PanelKeyCatcher.qml:54-57` into `PodmanView.qml:273`); the docs describe
forward `tab` only. Capital `X` removes just as `x` does
(`PanelKeyCatcher.qml:78`). The `Esc` chain has three steps — the help sheet,
then Podman's error, then close (`PodmanView.qml:268-272`) — and the docs
name two. `Panel.qml:53-56` exposes `open`, `close`, `show` and `hide` over
IPC where `README.md:141-147` lists only `toggle`, `tab`, `refresh` and
`stopAll`; AGENTS.md:74 tells agents to run `omarchy shell nixarchy.podman.bar
open`, a verb the README says does not exist.

`space` starting and stopping containers is the same class of problem but is
tracked with #19, because there the fix may be to change the behaviour rather
than to document it.

**Stale claims on the published site.**

`docs/index.md:118` still carries the pre-#14 prune caption — "`p` says
exactly what kind of thing goes" — which is the exact defect #14 was filed
against. `Model.pruneMessage` now names up to three targets, and the retaken
screenshot beside that caption shows the names. The caption contradicts the
image next to it, on the public page.

`docs/usage.md:99` says middle-click refreshes. `Panel.qml:81` calls
`refresh()`, which is containers only, not `refreshAll()` as `u` does — so
the Images and Volumes footers stay stale until the 10s timer. The
`docs/usage.md:152-167` table has no row for `?` or `tab`, and `:154` omits
the arrow keys that `PodmanView.qml:263` handles.

## Proposed outcome

- No two documents disagree. Where they described the same thing differently,
  one wording survives.
- Every key and every IPC verb that does something is written down, and
  nothing is written down that does not exist.
- The prune caption on the site matches the screenshot beside it.
- `Model.js:83-84`'s claim that the README quotes `SHORTCUTS` is true, or the
  comment goes.
- The settings question is answered by looking at a running shell, not by
  guessing, and the losing wording is deleted rather than softened.

## Affected users and systems

- `README.md`, `docs/usage.md`, `docs/index.md`.
- `Model.SHORTCUTS`, and so the `?` sheet, if keys are added there.
- Readers of the GitHub Pages site, which is the public face of the plugin.
- Possibly `Menu.qml`, if the live check shows the menu really does need a
  shell restart and that is worth fixing rather than documenting.

## Constraints

- Documentation only, wherever possible. If the live check turns up a real
  settings bug, that becomes its own issue rather than being fixed here.
- `Model.js:83-84` means the README's shortcut table and `Model.SHORTCUTS`
  must end up genuinely identical, not merely similar.
- AGENTS.md's own IPC example must agree with the README's verb list.
- Retake any capture a wording change makes wrong; `docs/img` is at 69% of
  its 8 MB budget.
- `space` stays out of scope — it belongs to #19.

## Open questions

1. **Does the menu need a shell restart for settings or not?** This needs
   `omarchy-restart-shell`, a settings change, and a look. Everything else
   here is mechanical; this one is a real unknown and decides whether we
   delete a paragraph or file a bug.
2. **Should `Model.SHORTCUTS` gain the undocumented keys** — Shift+Tab,
   capital `X`, the arrow keys, the first step of the `Esc` chain — or should
   the `?` sheet stay deliberately short and the detail live only in
   `docs/usage.md`? A sheet that lists everything is a sheet nobody reads.
3. **Should the four IPC verbs be documented, or reduced?** `show`/`hide` are
   exact duplicates of `open`/`close` (`Panel.qml:53-56`). Documenting four
   verbs where two would do is worse than deleting two of them.
