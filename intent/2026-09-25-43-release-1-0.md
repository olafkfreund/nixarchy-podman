# Intent: Call it 1.0

## Problem

The plugin has shipped as `0.2.0` since it was packaged, with no git tag and
no GitHub release — `git tag` and `gh release list` both return nothing. So
there is no way for anyone to say which version they are running, and
`omarchy plugin add` clones whatever `master` happens to be.

Twelve issues have closed against it, and the work behind them changed what
the plugin is rather than polishing it:

- **#19** — the button that stops every running container asked nothing. It
  asks now, naming what it will stop.
- **#20, #21** — the Prune button lied on the Containers tab, digest-pinned
  images rendered as `name@sha256`, the `ipv6` badge could never light, and a
  truncating `head` made a full list read as empty.
- **#22, #30, #17** — the menu ignored the screen it opened on, magnified
  itself with a transform that clipped content unreachably, and the `?` sheet
  could not be read in one view.
- **#23, #37** — the docs contradicted themselves and the code.
- **#24, #31** — the checks could not fail, and CI granted itself more than it
  used.
- **#38, #41** — the captures showed a theme nobody runs; the last dead code
  is gone.

That is a version number's worth of change, and none of it is recorded in one.

## Proposed outcome

- `manifest.json` says `1.0.0`, and the Nix store path built from it says so
  too.
- A `v1.0.0` tag points at a commit that built green.
- A GitHub release describes what changed and, plainly, what was not
  verified — so anyone installing it knows which parts were watched running
  and which were only reasoned about.
- Someone reporting a bug can say which version they are on.

## Affected users and systems

- `manifest.json`, which `flake.nix:32` uses to name the store path, so the
  package derivation changes.
- Anyone who installs via `omarchy plugin add` or the flake.
- The GitHub releases page, which is currently empty.

## Constraints

- **The tag must point at a commit that built green.** The version bump
  merges and CI passes before anything is tagged; a tag is the part people
  pull and is awkward to move.
- The release notes must say what was **not** verified. The stop-all
  confirmation from #19 — the most safety-relevant change in the set — has
  never been seen by a human, because it needs a pointer click and no input
  daemon was available. That belongs in the notes, not buried.
- Semantic versioning: this is `1.0.0`, not `1.0.0-rc` or `0.3.0`. The
  approver has chosen the number.
- `nix flake check` and the test suite green at the tagged commit.

## Open questions

1. **Does 1.0 wait for #38's videos?** The site currently mixes new stills
   with recordings of a menu that no longer looks like that. A release whose
   shop window is half stale is a real cost, and the videos are the only
   thing between here and a coherent page.
2. **Should the release be marked latest?** It is the first, so yes by
   default — but if the unverified stop-all path argues for caution, a
   pre-release flag is the mechanism for saying so without withholding it.
3. **Is there anything in AGENTS.md's known follow-ups that should block?**
   Wiring p620 and razer to this flake is listed there and is not done; if
   1.0 is meant to be the version those hosts run, that ordering matters.
