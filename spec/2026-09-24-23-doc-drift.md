# Spec: The documentation contradicts itself and the code

## Design

Every claim in the intent was re-verified against `master` before this spec
was written. All of them still hold, with the corrections noted below.

### Sequencing: #19 owns part of this

`fix/19-stop-all-confirm` already changes `README.md`, `docs/usage.md` and
`Model.SHORTCUTS` — it documents `space`, adds the stop-all question and folds
`space` into the `enter` row. This branch is cut from `master`, where none of
that exists.

**So #19 must merge first, and this branch rebases onto it.** Two branches
editing the same shortcut table in different directions is how one silently
reverts the other. The items #19 owns are listed here as out of scope, not
repeated.

### The contradictions

**Settings propagation.** `README.md:136` says the menu reads settings "each
time it opens"; `docs/usage.md:195` says "only after the shell restarts,
because of an Omarchy shell issue". `Menu.qml:70` does call `readSettings()`
on every `open()` — but it reads through `shell.barConfig`, which may itself
be stale, so the code does not settle it.

**This is the one item that cannot be resolved by reading.** It needs a
settings change and `omarchy-restart-shell` on a live desktop. The spec
therefore specifies both outcomes rather than guessing:

- *If the menu does pick up changes without a restart:* `usage.md:194-200`
  loses the paragraph and the `omarchy-restart-shell` block, and the README
  stands.
- *If it genuinely needs a restart:* the README's sentence is corrected to
  match `usage.md`, and a new issue is opened against `Menu.qml`, because
  re-reading settings on every `open()` while the source is stale is a bug in
  its own right, not a documentation problem.

Either way one wording survives. Softening both to hedge is not an option —
that is how the contradiction started.

**The footer.** `README.md:36` says the footer reports the current tab;
`docs/usage.md:111` says images and volumes only. Verified by running it:
`usageText(usage, "containers", [])` returns `"2.00 GB · 500 MB reclaimable"`.
The README is right; `usage.md:111` is corrected.

**The duplicate `tab` row.** `README.md:55` and `:60` are the same row with
the clauses reversed. `:60` goes. `Model.js:83-84` claims the README quotes
`SHORTCUTS`, and `SHORTCUTS` has one `tab` entry.

### The undocumented behaviour

The intent listed five items. Re-checking each against `SHORTCUTS` changes
what needs doing:

- **Arrow keys are already in the sheet** — `SHORTCUTS` carries
  `"h  l  ← →"` and `"j  k  ↑ ↓"`. The gap is `docs/usage.md:154`, which
  writes only `` `j` / `k` ``. A usage.md fix, not a sheet fix. The intent
  implied otherwise.
- **Shift+Tab** steps backwards and is in neither. `SHORTCUTS`'s `tab` row
  becomes `tab  shift+tab` with the text extended to say so.
- **The `Esc` chain** has three steps; the sheet's row names two. It becomes
  "Close the shortcut sheet, dismiss Podman's message, leave the filter, then
  close the panel."
- **Capital `X`** gets nothing. It is the shift of a documented key, and a
  reference that lists both cases of every letter is a worse reference.
- **`space`** belongs to #19.

No new rows: two existing rows are extended. A sheet that lists everything is
a sheet nobody reads, and #17 already reports it overflowing a short card —
growing it would make an open bug worse.

The README's table mirrors both edits, since `Model.js:83-84` requires it.

### IPC: delete the aliases rather than document them

`Panel.qml:53-59` exposes seven verbs: `open`, `close`, `show`, `hide`,
`toggle`, `refresh`, `stopAll`. The README documents four — and `show`/`hide`
are exact aliases of `open`/`close`, calling the same two functions.

**Delete `show` and `hide`; document `open` and `close`.** Documenting two
names for one action teaches the reader there is a difference to look for.
`open`/`close` are the canonical pair: AGENTS.md:74 already instructs agents
to run `omarchy shell nixarchy.podman.bar open`.

This is an external surface, so it is the approver's call. The risk is
someone scripting an undocumented alias — low, since the only way to discover
them was to read `Panel.qml`. If the approver prefers safety, the fallback is
to document all six; that is two more lines of prose and no code change.

### The stale site caption

`docs/index.md:118` reads "`p` says exactly what kind of thing goes" — the
pre-#14 behaviour, and the exact defect #14 was filed against. The image
beside it, `confirm-prune.png`, was retaken in #11 and shows the names. The
caption is replaced with wording that matches the picture: "`p` names what it
will take, and has Cancel selected."

### Middle-click

`docs/usage.md:99` says middle-click refreshes. `Panel.qml:81` calls
`podmanState.refresh()`, which is containers only; `u` calls `refreshAll()`.
The sentence gains the distinction.

**Not proposed: changing `Panel.qml` to call `refreshAll()`.** That would make
the docs true by changing behaviour, in a documentation issue, without anyone
deciding the middle button should cost three more queries. If the difference
is unwanted, that is its own issue.

## Alternatives rejected

**Fix the docs to match whatever the code does, everywhere.** Rejected for the
settings item specifically: if the menu really needs a restart, that is a bug
and documenting it as behaviour would close the door on fixing it.

**Add every undocumented key to the `?` sheet.** Rejected: #17 already reports
the sheet overflowing a short card, and a complete reference is not a quick
reference.

**Leave the site caption and retake the screenshot to match it.** Rejected —
the caption describes behaviour #14 deliberately removed.

## Risks

- **This branch and #19 both edit the README's shortcut table and
  `Model.SHORTCUTS`.** Mitigated by merging #19 first and rebasing. If that
  order is not kept, one will silently revert the other's row.
- **Deleting `show`/`hide` is an external surface change** in a documentation
  issue. Called out above; the approver may keep them.
- **The settings item may open a second issue** rather than closing cleanly.
  That is the correct outcome if the menu really is stale, and the PR should
  not be held for it.
- **No capture is affected.** The wording changes do not alter any surface;
  `confirm-prune.png` already shows what the corrected caption describes.
  Confirm by eye before concluding no retake.

## Verification

   the same meanings, checked row by row. One `tab` row, not two.
3. `grep -c 'function .*(): void' Panel.qml` is 5, and every one appears in
   the README's IPC block.
4. Live, on the desktop, in this order:
   - Change a setting, reopen the menu **without** restarting the shell.
     Record which way it goes; this decides the settings wording and possibly
     opens an issue.
   - `omarchy shell nixarchy.podman.bar open` and `... close` both work.
   - Shift+Tab steps backwards through the tabs.
   - `esc` closes the shortcut sheet first, as the amended row now claims.
   - Middle-click the glyph, then check whether the Images footer is stale —
     confirming the distinction the sentence now draws.
