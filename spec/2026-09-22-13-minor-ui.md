# Spec: Minor UI polish from the #10 live test

Five items, one plan step each, numbered as in the intent.

## Design

### 1. The shortcut sheet is opaque

`ShortcutSheet.qml` fills its background with
`Qt.rgba(background.r, background.g, background.b, 0.97)`. That lets 3% of whatever
is underneath through, which is enough for bright list text on a dark theme to read
through the sheet, as seen on razer. The alpha becomes `1`. It still uses the theme's
colour, so no hardcoded colour is involved.

The intent's other suspects, drawing order and the menu's 1.45× scale, are ruled
out: the sheet has `z: 5` over the list inside the same scaled view.

### 2. The sheet lists `Tab`, and the new `esc`

`Model.SHORTCUTS` changes in two places:

- **Move** gains `{ keys: "tab", text: "Next tab in the full-screen menu; the next bar panel in the popup" }`.
  The same list serves both surfaces, and `Tab` means different things in each, so
  the line says both.
- **`esc`** becomes "Dismiss Podman's message, leave the filter, then close the
  panel" (see item 5).

The existing test "every key the panel actually listens for is written down" gains
`"tab"`. The README key table and `docs/usage.md` get the same two lines.

### 3. The menu card keeps its top edge

`Menu.qml` places the card at
`y: Math.max(Style.gapsOut, Math.round((panel.height - height) / 3))`, so the top
edge moves with the card's height. It becomes a fixed top:
`y: Math.max(Style.gapsOut, Math.round(panel.height * 0.075))`.

The card's height is already capped at `panel.height * 0.85`, and 0.075 is half of
the remaining 15%. So the tallest card is centred, a shorter one grows downward from
the same top edge, and the tabs and filter never move. This is layout only, and is
verified live.

### 4. Rows stay put under the pointer, and the cursor follows its container

There are two parts.

**The pointer.** While the pointer is over the list, the row order is held. This
extends the approved decision (hold after a click, until the pointer leaves) to any
hover, because a re-sort under a hovering pointer is the same hazard whatever caused
it: a click, a keypress, or a container that changed outside the panel.

- `ResourceList.qml` adds a `HoverHandler` on its ListView and exposes
  `readonly property bool pointerInside`.
- `PodmanView.qml` keeps `property var heldIds: null`. When `pointerInside` becomes
  true, it snapshots the ids of the current rows in order; when it becomes false, it
  sets the snapshot back to `null`.
- A new `Model.holdOrder(sections, heldIds)` reorders **within each section**. Held
  ids keep their snapshot order, new ids go after them in natural order, and gone
  ids drop out. `PodmanView`'s `sections` becomes
  `Model.holdOrder(<today's sections>, heldIds)`. Section headers are recomputed by
  `rowsForSections` as today, because the reorder happens before the rows are built.
- Rows still appear and disappear while held; only moves wait. Leaving the list
  releases the hold, and the list re-sorts once.

**The keyboard.** Today the cursor is an index. After a re-sort the same index can
point at a different container, and Enter or `x` then acts on it.

- A new `Model.cursorFollow(rows, id, index)` returns the index of `id` in the new
  rows if it is still there, and otherwise `clampCursor(index, rows.length)`.
- `PodmanView.onRowsChanged` uses it with the id of the row the cursor was on, which
  it records whenever the cursor moves.

### 5. Podman's refusal reads in full and `esc` dismisses it

- `Model.errorText` shortens every 64-hex id to 12 characters (`shortId`), then keeps
  up to 300 characters instead of 160. Podman's refusal on razer was
  `image used by <64 hex>: image is in use by a container: consider listing external containers and force-removing image`.
  It fits once the id is short. The line already word-wraps.
- `esc` while the message is showing clears it. In `PodmanView`'s key catcher
  `onCloseRequested`, the order becomes:
  1. help sheet open → close it;
  2. else, `podman.lastError !== ""` → clear it;
  3. else, close the panel.

  In the filter field, `esc` keeps its own two steps (clear the text, then leave).
  The error rule applies only once focus is back on the list.

## Alternatives rejected

- **Sheet: raising `z` or disabling the list under it.** The cause is the alpha;
  anything else would leave 3% bleed.
- **Card: vertical centring.** It still moves with the height, only half as much.
- **Item 4: holding only after a click** (the literal option (a)). It needs click
  plumbing through every action, and misses a re-sort caused by a refresh while the
  pointer hovers. Hover-hold covers both, with less code.
- **Item 4: ignoring a second click for a moment, or stopping the running-first
  sort.** Rejected at approval.
- **Item 5: a new key such as `e` for dismissing.** Rejected at approval in favour of
  `esc`. Another letter would also have to stay clear of every tab's keys.
- **Item 5: dropping the id from the message entirely.** The short id is still how
  someone finds the container Podman means.

## Risks

- **Hover-hold could keep a list visibly "wrong"** (a started container not moved to
  the top) for as long as the pointer rests on it. That's the intended trade: the
  move happens the moment the pointer leaves.
- **`esc` changes meaning while an error shows.** Someone used to `esc` closing the
  panel needs a second press. The sheet and the docs say so, and the error line's ×
  still works.
- **The fixed card top on very short screens:** at 0.075 of the height the card
  still fits, because its height cap is 0.85. Check on a 1080p screen; others are
  unverified.
- **`holdOrder` must not cross sections.** A container that changes project
  (practically never) moves section even while held. The tests pin
  within-section-only behaviour.

## Verification

- Node tests that fail first:
  - `SHORTCUTS` includes `tab`;
  - `errorText` on razer's exact refusal returns the whole text, with a 12-character
    id;
  - `holdOrder`: order kept, new id appended, gone id dropped, sections untouched;
  - `cursorFollow`: follows the id, and clamps when the id is gone.
- `nix flake check`, `nix build`, and `omarchy plugin validate` on a fresh clone.
- Live on razer, `demo-*` only, reading every dialog before any confirm; no prune is
  needed for this change:
  - `?` in the menu: no list text visible through the sheet (screenshot);
  - switching tabs `1`–`4` in the menu: the tab strip's y is identical in every
    screenshot;
  - pointer on the list, click ▶ on a stopped demo container: it does not move until
    the pointer leaves;
  - keyboard: put the cursor on a demo container, press Enter to start it, then Enter
    again: the same container stops (checked with `podman events`);
  - remove the in-use demo image: the refusal reads in full, `esc` clears it, and a
    second `esc` closes the panel;
  - `qs log` clean: no binding loops and no `ResourceList` errors.
- Docs: `docs/usage.md` key table (`tab`, and `esc`'s new first step) and the README
  key table. `shortcuts.png` and `podman-refuses.png` are retaken in #11.
