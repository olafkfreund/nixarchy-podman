### 3. `labelMap` gets an object-form fixture from real output — question 2

The intent worried that a fixture would encode my assumption about Podman 5
rather than its behaviour. It does not have to: `podman images --format
'{{json .Labels}}'` on this machine emits, verbatim,

```json
{"com.github.containers.toolbox":"true","io.buildah.version":"1.43.2","org.opencontainers.image.title":"fedora-toolbox"}
```

and `null` for an image with no labels, while `podman network ls` emits `""`.
So three real shapes are available and all three get asserted, alongside the
comma-separated string form the existing fixtures already exercise.

The branch under test is `labels.length === undefined`, which is how
`labelMap` tells an object from a string — the Qt-sequence-wrapper distinction
AGENTS.md warns about. A test that passes an object with a numeric `length`
property pins that the check is about shape, not truthiness.

### 4. `copyTooltip` gets four assertions — question 3

The intent asked whether four is over-testing wording. It is four one-line
branches and four one-line assertions, and the failure it catches is a
reordered `if` handing the images tab the container string — which is silent,
user-visible and exactly the kind of thing nobody notices in review. Four.

### 5. `itemKey` gets three assertions

Three lines of code, but it is the #6 fix: an image with several tags needs a
`rowId` distinct from its `id`, or the list leaves stale duplicate rows.

- `rowId` set → returns `rowId`
- `rowId` absent → returns `id`
- **`rowId` an empty string → returns `""`, not `id`**

The third is the one worth having. `itemKey` uses `!== undefined` rather than
a truthiness check, and a future simplification to `item.rowId || item.id`
would pass the first two assertions and break this one.

### What does not change

No behaviour. The deletions remove unreachable code; the tests pin what the
functions already do. If a test fails when written, that is a finding to
report — not something to adjust the test around. `Panel.qml` stays
byte-identical.

## Alternatives rejected

**Delete `rowsFor` and rewrite its fifteen callers.** Churn for no runtime
gain, in tests that are correct as they stand.

**Leave `containerById` in case something wants it.** It is a one-line alias
for `itemById`, which is right there; anything wanting it can call that.

**Skip `labelMap`'s object branch** because the shape was uncertain. It is not
uncertain — it was read off this machine.

**Test `copyValue` too**, which sits beside `copyTooltip` and is equally
unasserted. Out of scope: this issue lists three helpers, and widening it
during implementation is how a cleanup becomes a rewrite. Worth its own look.

## Risks

- **A test may fail when written.** That is the point of writing them, and the
  constraint says to report rather than paper over. The most likely candidate
  is `labelMap` on the `null` input, where `String(null)` and the
  `labels &&` guard interact.
- **Deleting a signal is an API change to a QML component**, even an
  unemitted one. `ResourceList` is internal to this plugin and
  `grep` confirms nothing connects to it, but an external consumer would
  break. There is no external consumer.
- **No packaging or runtime risk.** No new file, no `files` list change, no
  capture affected.
